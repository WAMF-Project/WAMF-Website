Development Roadmap

Where WAMF is today, and where it is heading.

WAMF is under active development. This roadmap reflects the current direction of the project, but priorities may evolve through real-world testing, feedback and practical use.

Current stable release

v0.4.3 – Security Maintenance

WAMF v0.4.3 is the latest stable release. It strengthens embedded-navigation URL validation and security regression testing while retaining the Frigate-based bird detection pipeline. It introduces no new application features or dependency upgrades.

Two known protobuf vulnerabilities remain documented accepted risks, not patched fixes. Read the published release, installation guide and security guidance.

Historical release

v0.4.2 – Security and Setup Maintenance

v0.4.2 strengthened detection rendering, event identifier validation, login throttling and media handling. It introduced a private, single-use first-run administrator setup link and improved configuration saves. Known protobuf vulnerabilities remained accepted risks. Read the v0.4.2 release.

Historical release

v0.4.1 – Security Maintenance

v0.4.1 updated compatible Python dependencies and the container runtime, reduced unused container components and preserved existing configuration, media and credentials. Known protobuf vulnerabilities remained unresolved. Read the v0.4.1 release.

Historical release

v0.4.0 – Platform Stabilisation

Released on 18 September 2026, WAMF v0.4.0 establishes a stable, deployable foundation for self-hosted wildlife monitoring using Frigate as the detection source.

  • Stable Frigate event processing over MQTT
  • AI bird species identification
  • Observation storage using SQLite
  • Snapshot and clip archiving
  • Media retention tools
  • Recent detections and activity views
  • Species metadata and reference information
  • System health and administration tools
  • First-run configuration and administrator bootstrap
  • Reliable restart and shutdown handling
  • Official Docker deployment through GHCR
  • Validated compatibility with Frigate 0.17.2 and 0.18.0
  • Deployment and portability testing across multiple hosts
  • Public website and documentation

Future development

Raven

Raven is a future development direction. The WAMF Core and Scouts ideas below are exploratory and are not available in the stable release.

  • Detection source abstraction layer
  • Shared WAMF event contract
  • Frigate as a Scout-compatible detection source
  • Direct RTSP detection paths
  • Support for alternative inference hardware and backends
  • Foundations for Raspberry Pi and AI camera Scouts
  • Scout health and configuration
  • Improved and versioned external API
  • Webhook and integration support
  • Review of the WAMF Core web and API architecture
  • Foundations for distributed wildlife monitoring
Future

Longer-term ideas – Distributed Wildlife Monitoring

Later releases can build on the WAMF Core and Scout architecture to support increasingly varied wildlife monitoring hardware and distributed deployments.

  • Additional wildlife categories beyond birds
  • Additional classification models
  • More Scout hardware and detection backends
  • Distributed and remote capture devices
  • Improved multi-camera and multi-Scout workflows
  • Richer statistics and long-term activity trends
  • Expanded external integrations
  • Community-driven extensions

Project Philosophy

WAMF is designed for wildlife monitoring rather than security. It aims to turn camera detections into useful wildlife observations while remaining practical for self-hosted systems and experimental hardware.

  • Open source
  • Self hosted
  • Practical to run
  • Friendly to hobbyists and experimenters
  • Useful before it is complex
  • Extensible without becoming bloated
